## 1. 背景与问题

大学物理是一门"听懂不难、听懂不会做题"的课。常见的教学困境有三：

1. **学情看不见。** 教师在一百人的阶梯教室里，只能靠随堂提问和期末考试这两头判断学习状态，中间的过程是黑箱。
2. **作业反馈滞后。** 学生在习题册上写下推导，教师往往要等到批改完才知道他在哪一步卡住，反馈已经隔了一周。
3. **实验数据是"用完即弃"的。** 学生做完超声测距实验，记下三个数字就填进实验报告，数据的意义、误差从哪来、下一组该怎么改，全部留在纸上。

传统数字教学工具能解决其中一两项，但几乎都做不到**过程可解释**——分数从哪来、建议从哪来，学生说不清，教师也复核不了。

本作品用一条完整的学习闭环回答这三个问题：

> **诊断 → 项目匹配 → 任务闯关 → 虚拟实验 → 学习报告**，并让每一步留下的**过程证据**同时服务于学生和教师。

## 2. 作品概述

平台由**两个能力域**组成，共用一套账号、一套导航、一套品牌：

### 2.1 AI 智能课堂域（OpenMAIC 二次开发）

- 一键生成：输入章节主题或上传教材 → 生成**课件（Slides）+ 测验（Quiz）+ 交互仿真（Interactive）+ 项目式学习（PBL）** 的完整课堂
- 多智能体课堂：AI 教师与 AI 同学参与讨论、圆桌辩论，可被点名回答
- 白板演算：教师智能体实时演算、画图、写公式
- 导出：`.pptx`（每页贴顶校名页眉 + 贴底校名页脚）/ 单文件离线 HTML（页眉 + 页脚，均含校名与"示例数据"说明）/ 课堂 ZIP
- **物理化改造**（本次二开的核心）：把"大学物理"的领域约束注入生成管线
- **模型供给可换成腾讯云自家网关**：部署时把 `MAKERS_MODELS_KEY` 配到 EdgeOne 控制台，
  即可用 [EdgeOne Makers Models](https://cloud.tencent.com/document/product/1552/132748)
  统一网关调用多家主流大模型（OpenAI 兼容协议、`https://ai-gateway.edgeone.link/v1`），
  **现场演示不必自备第三方厂商账号**；也可随时改回 DeepSeek / Kimi / MiniMax 等任意厂商。
  只配这一个 Key 就够用：`DEFAULT_MODEL` 缺省时由代码自动推导为
  `openai:@makers/deepseek-v4-flash`（带 `openai:` 前缀，否则解析不出 provider）。
  想确认你的账号实际能用哪些模型，跑 `node scripts/check-makers-models.mjs`。
  免费版配额见 [《限制与配额》](https://cloud.tencent.com/document/product/1552/132789)：
  Models 网关的内置模型免费额度 50 万 token/月

### 2.2 物理学习工作台域（自建教学闭环）

- **学生端 8 视图**：学习总览 / 学情诊断 / 章节与知识图谱 / 项目匹配 / 任务闯关 / AI 助教 / 虚拟实验 / 学习报告
- **教师端 5 视图**：教学驾驶舱 / 班级画像 / 课程项目矩阵 / 评价复核 / 教学洞察
- 客户端持久化（localStorage 版本化包络），退出登录不丢数据
- 破坏性动作二次确认 + 24 小时可恢复快照

### 2.3 两域的连接点

```
学情诊断维度得分 ──▶ 决定 AI 课堂的讲解深度与推荐项目
AI 课堂的测验 / 讨论记录 ──▶ 回流到学习报告的"过程证据"
```

诊断发现"电磁学概念混淆"，教师在 AI 课堂里就该多花一节课在电场与电势；
学生在 AI 课堂的讨论与答题记录，又会出现在他的学习报告里，与实验数据并列。

## 3. 二开说明：改了什么，为什么改

这是本作品与"直接用 OpenMAIC"或"自己写一个物理网站"的根本区别。

### 3.1 基底选型：为什么是 `release/1.1.x` 而不是 `main`

OpenMAIC `main` 分支（v1.2.0+）改为 server-first 架构：课程生成在服务端常驻进程中执行，
且 `DATABASE_URL` 是硬性启动条件，缺失即拒绝启动。这与"部署到腾讯云 EdgeOne Pages"
（无状态边缘运行时，无长驻进程、无固定数据库）在架构上互斥。

`release/1.1.x`（v1.1.4）则**默认使用浏览器存储**（课程文档 / 学习者运行时 / 设备 KV /
资源全部落在 IndexedDB），官方支持 Serverless 部署，并保留全部 AI 课堂能力。
因此本作品以 `release/1.1.x` 为基底，在其之上实现"无数据库"形态。

### 3.2 逐条对照

| # | 改动 | 上游原状 | 本作品做法 | 动因 |
| --- | --- | --- | --- | --- |
| 1 | **物理教学域移植** | 无 | 新增 `lib/physics/`：纯领域层 11 文件 3 687 行 + 浏览器适配层 8 文件 1 106 行，共 4 793 行 | 复用已验证的教学逻辑，避开"重写"风险；纯领域层零框架依赖，可直接单测 |
| 2 | **物理工作台 UI** | 无 | 新增 `components/physics/`：外壳 + 登录 + 命令面板 + 学生 8 视图 + 教师 5 视图 | 交付"从登录到功能完整"的成品 |
| 3 | **校本内容层** | 无 | 新增 `lib/school/`：identity / branding / curriculum / ideology / rubric / campus 六个模块 | 校名、班级、章节、实验、思政、评价量表全部集中一处，不散落 |
| 4 | **品牌层** | 上游默认紫色 `#722ed1` | 主色改校色天蓝 `#0369a1`；中文字体栈（苹方/微软雅黑）前置；打印样式 | 让成品一眼看出是本校产品 |
| 5 | **生成管线物理化** | 通用课件提示词 | 应用层注入物理领域约束（符号量纲 / 常见误区 / 实验安全 / 课程思政 / 校内上下文 / 智能体人格） | 一次约束贯穿全部场景类型，且**不改动上游生成模板** |
| 6 | **预置课堂包** | 无 | 6 个物理章节的完整课堂包（讲演页 + 测验，部分另含自包含交互仿真） | 零配额、零网络也能完整演示"生成→上课→导出" |
| 7 | **边缘部署改造** | 默认面向 Docker / Vercel + PostgreSQL | 移除 `render-service/` 与 `app/api/persistence/`；新增部署形态断言；关闭 Agent Workbench 与后台 runner | 与 EdgeOne 的无状态边缘模型对齐 |
| 8 | **`build:packages` 修正** | pnpm workspace 内混用 `npm run build` | 改为 `pnpm -r --filter ... run build` | npm 不认识 `workspace:` 协议，CI 下易失败 |
| 9 | **跨平台原生模块** | 无 | `pnpm-workspace.yaml` 增加 `supportedArchitectures`（含 linux-x64） | `sharp` / `@napi-rs/canvas` 在 EdgeOne 构建期需要 linux-x64 产物 |
| 10 | **`typecheck` 脚本** | 上游无 | 新增 `pnpm typecheck` | 把类型检查纳入验收门槛 |

### 3.3 有意保留的部分

| 保留项 | 原因 |
| --- | --- |
| `pg` / `@electric-sql/pglite` 依赖 | `lib/persistence/server-provider.ts` 在类型层静态引用 `pg`，删除依赖会破坏类型检查。**依赖在，运行时永不启用**——没有任何 `DATABASE_URL`，该路径不可达 |
| Agent Workbench 与 `/workspace` 代码 | 上游自带服务端门禁：`NEXT_PUBLIC_PRO_WORKBENCH_ENABLED` 未设时，中间件对 `/workbench` 返回 404，`/workspace` 自动重定向。**功能已完全关闭**，删除 20 余个文件只增加回归风险，不改变部署行为 |
| `app/api/export-video/` | 上游已实现优雅降级：未设 `RENDER_SERVICE_URL` 时自动改为导出项目 ZIP。删除反而破坏降级路径 |

### 3.4 部署形态断言

平台新增 `lib/config/deployment-mode.ts`，在 `instrumentation.ts` 的 `register()` 中校验：

```ts
assertDeploymentConfig(detectDeploymentMode());
```

若在边缘部署中误设了 `DATABASE_URL` / `NEXT_PUBLIC_PERSISTENCE` /
`NEXT_PUBLIC_PRO_WORKBENCH_ENABLED` / `OPENMAIC_AGENT_RUNTIME_ENABLED`，
**进程直接启动失败并打印原因**。宁可启动失败，也不让评委在现场看到"点了没反应"。

## 4. 教学闭环与过程证据

### 4.1 五阶任务模型

每一关都要求留下**可复核的过程证据**，而不只是一个"完成"勾选：

| 关卡 | 能力阶 | 过程证据 |
| --- | --- | --- |
| 第一关 情境认知 | 知识理解 | 物理问题结构图、关键物理量清单 |
| 第二关 原理建模 | 专业应用 | 核心物理关系、模型假设、自变量/因变量/控制变量 |
| 第三关 方案设计 | 创新实践 | 方案框图、两方案对比、评价指标 |
| 第四关 实验验证 | 创新实践 | ≥5 组数据、误差或不确定度、一次基于数据的方案修改 |
| 第五关 协同创生 | 团队协作 | 分工记录、作品或成果视频、答辩与个人反思 |

### 4.2 三条不可让渡的产品原则

1. **过程证据 > 最终分数。** 报告汇总的是过程记录；分数只是其中一项。
2. **破坏性动作必须可逆。** 重置记录 / 重新诊断 / 切换项目，都有二次确认 + 24 小时可恢复快照（顶部横幅一键撤销）。
3. **教师保留最终判断权。** AI 只产出**建议分**与理由；教师复核后的分数始终覆盖建议分，学习报告以复核分为准。界面上这一点始终可见。

### 4.3 四阶能力量表

知识理解 / 专业应用 / 创新实践 / 协同创生，每一阶有分段锚点（扎实 / 基本掌握 / 有缺口 / 需重建），
AI 建议分与教师复核共用同一套量表，因此教师能快速判断建议分是否合理。

## 5. 课程思政与校本内容

`lib/school/ideology.ts` 为每一章挂一条思政锚点，锚点必须**从该章的真实物理内容自然生长**：

| 锚点 | 物理生长点 | 落点 |
| --- | --- | --- |
| 严谨求实 | 有效数字、不确定度、系统误差 vs 随机误差 | 结论建立在误差分析之上，而非"看起来对" |
| 科学方法 | 质点模型、理想气体模型、匀强电场模型 | 说得清"模型在什么条件下成立" |
| 节能与绿色发展 | 能量流图、效率优化 | 物理定律是技术乐观主义的边界，也是护栏 |
| 工匠精神 | 转动惯量测定、条纹计数 | 训练规范、复现与迭代，而非"做砸了怪仪器" |
| 科技报国与工程伦理 | 超声测距、漏磁检测、无线供能 | 把精度与误报率换算成"关系到谁的安全" |

校内实验项目清单（13 项，示例）与章节矩阵对齐，**超声测距**同时以两种形态呈现：
工作台的独立 Lab 页（SVG 波形 + 误差散点）与 AI 课堂里的自包含交互仿真
（HTML，无外部依赖，断网可用）——后者让 AI 教师智能体可以实时操作、点亮、提示。

## 6. 技术架构

### 6.1 分层

```
┌─────────────────────────────────────────────────────────┐
│  表现层                                                   │
│  app/page.tsx（AI 课堂首页 + 物理门户）                     │
│  app/physics/[view]（学生 8 视图）  app/teacher/[view]（教师 5 视图）  │
│  components/physics/  components/portal/                  │
├─────────────────────────────────────────────────────────┤
│  领域层（纯函数，零 React / 零 DOM，可单测）                │
│  lib/physics/{types,data,engine,report,local-store}       │
│  lib/physics/prompts/（物理领域约束）                       │
│  lib/physics/presets/（预置课堂包）                         │
├─────────────────────────────────────────────────────────┤
│  校本层（学校 / 课程 / 班级 / 思政 / 量表）                  │
│  lib/school/{identity,branding,curriculum,ideology,rubric,campus} │
├─────────────────────────────────────────────────────────┤
│  引擎层（OpenMAIC 原生，未改动）                            │
│  @openmaic/{dsl,generation,renderer,storage,editor,importer}  │
│  lib/{orchestration,playback,action,ai,export,…}          │
├─────────────────────────────────────────────────────────┤
│  持久层                                                   │
│  课程与学习记录 → 浏览器 IndexedDB / localStorage（无数据库）  │
│  可选 EdgeOne KV（目录索引）/ Blob（生成媒体）              │
└─────────────────────────────────────────────────────────┘
```

### 6.2 关键技术选择

| 选择 | 理由 |
| --- | --- |
| 物理域保持纯函数 | 可单测、可迁移到任何前端框架；旧项目领域逻辑整体移植、不重写（纯领域层累计 3 687 行，含新增的校本剧本与物理约束） |
| 领域约束在应用层注入 | 不改上游生成模板，物理知识集中一处，一次约束覆盖全部场景类型 |
| 预置包用纯函数构建课堂文档 | DSL 的坐标、主题、场景顺序必须自洽，集中构造 + 单测可在上游升级时快速发现不兼容 |
| 交互仿真写成自包含 HTML | 零外部依赖，断网可用；也能被 AI 课堂直接加载 |
| 服务端环境变量持有模型 Key | 密钥不进入客户端包；浏览器端仅作现场兜底 |
| 课程记录走浏览器强一致存储 | EdgeOne KV 是 60s 最终一致，课程与学生记录不能容忍两次刷新看到不同内容 |

### 6.3 数据流

```
教师输入章节 / 教材
   → buildPhysicsRequirement() 追加物理领域约束
   → /api/generate → @openmaic/generation（outline → scenes）
   → Stage DSL → /app/classroom/[id]
       ├─ Slides（旁白 + 聚光 + 激光笔）
       ├─ Quiz（自动判分 + 解析）
       ├─ Interactive（自包含 HTML 仿真）
       └─ 多智能体讨论 / 圆桌（白板演算）
   → 记录回流 → lib/physics/engine 汇总
   → 学习报告（Markdown / JSON / 打印）→ 教师复核（覆盖 AI 建议分）
```

## 7. 创新点

1. **"过程证据"作为一等公民。** 报告、评价、复核全部围绕过程证据组织，
   AI 建议分只是其中一项，且教师可覆盖。这在同类 AI 教学产品中少见。
2. **物理领域约束的管线级注入。** 不改上游模板，在应用层一次注入，
   使符号规范、量纲自检、常见误区、实验安全、课程思政同时作用于
   课件、测验、仿真与 PBL——而不是只作用于课件。
3. **一个实验的两种形态。** 同一套物理模型既是工作台的 Lab 页，
   也是 AI 课堂里可被 AI 教师操作的 Interactive 场景。
4. **零数据库的边缘部署。** 通过基底的版本选型把"必须自建 PostgreSQL"
   变成"浏览器即可"，并用启动断言把误配置挡在门外。
5. **三级降级的演示韧性。** 真实 LLM → 本地确定性引擎 → 预生成课程包，
   断网与限额都不影响演示完整度。后两档各管一段：本地确定性引擎负责工作台
   里的诊断评分、项目匹配、评价建议与实验仿真；预生成课程包负责 AI 课堂的
   "生成"环节——没有 key 时直接导入已备好的 6 个物理章节课堂。
6. **可逆的破坏性动作。** 24 小时快照 + 顶部横幅撤销，把"不敢让学生试错"
   变成"可以放心试错"。

第 7 条最值得记录：它的表现是"页面能打开、SSR 文字正常、按钮全哑"，
只看构建日志（EXIT=0）完全发现不了，**只有在浏览器里点一下才会暴露**。

这一条我们走了一个完整的弯路，值得如实记下来——**因为我们最初的归因是错的**。

**最初的判断**：standalone 形态下 `next start` 不提供静态资源路由，于是我们用
`NEXT_PHASE` 把 `output` 判定"固化"到构建期，并推测"产物形态与运行期判定不一致"
会让静态资源请求直接抛错（`server/lib/router-utils/filesystem.js` 的
`setupFsCheck` 分支），从而导致 chunk 500。

**独立复审用对照实验推翻了这条推理链**：在 Next 16.3.3 上，用**同一份产物**、
只改运行期的 `output` 判定值，standalone 与非 standalone 两种形态下
49 个客户端 chunk **全部 200**，并没有出现 500。也就是说
"形态不一致 → chunk 500"这条因果链并不成立。
（顺带也发现 `NEXT_PHASE` 在 `next build` 期间同样取不到值——Next 把它作为
`loadConfig` 的**函数入参**传入，不是环境变量——于是 `output` 恒为 `undefined`，
standalone 产物永远不再生成，上游 `Dockerfile` 的自托管路径被打断。
这一条已恢复为按环境变量判定。）

**真实成因**：**运行中的 `next start` 进程与磁盘上的新构建产物不是同一份**。
我们一边跑着旧进程、一边重建 `.next`，新构建删掉了旧 chunk 文件，
而旧进程返回的 HTML 仍按**旧 BUILD_ID** 去引用那些已被删除的 chunk，
于是客户端 JS 拉不到 → React 不水合 → 所有 `onClick` 静默失效。
换成"重建后重启进程（或换新端口）"之后，症状立刻消失。

**我们从中得到的教训有两条**：一，修复要问"证据支持这个因果吗"，而不只是"结果对不对"——
一个能自洽解释现象的错误因果，会让人把修复做在错误的地方；二，这种
"页面文字正常但功能全哑"的故障只有自动化检查才拦得住，所以它必须被固化成
一条可复现的检查项。

因此我们做了两件事：把 `scripts/check-physics-e2e.mjs` 固化为 21 项自动检查
（启用口令时 24 项）
（路由首帧水合安全、chunk 全 200、口令门禁四项、模型降级前提），写进部署手册
与验收清单；并在部署手册里补上 **BUILD_ID 一致性核对**——重建后先重启服务、
再比对 `.next/BUILD_ID` 与页面引用的 chunk 是否同源同版本，才算验证通过。

第 8 条同样如此：预置包的 PBL 场景**结构上存在**、单测也能校验字段齐全，
但课堂播放器用的是另一套"可运行性"判据（`isRunnablePBLProjectV2`），
判据不过就静默降级。修复后新增的 `tests/physics/pbl-render.test.tsx`
直接调用课堂渲染器做端到端断言，把"结构合法"升级为"真的渲染得出来"。

### 8.5 断网可用性实测（2026-10-22）

「断网也能演示」是硬要求，但它只有一条路能证明：**真的把网拔掉**。
我们为此写了一个本地代理（"加载后熄火"模式）：页面加载完成后销毁所有已建立连接、
拒绝新连接——等价于现场拔网线，而不是靠浏览器 DevTools 的离线开关。

第一轮实测就暴露了两个只有运行起来才看得见的问题：

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 9 | 断网后点侧栏切视图，**整页被换成框架错误页** | 视图 id 放在 URL 路径里，切视图走框架路由；动态路由必须拉 RSC payload（`text/x-component`），断网时拉不到，框架把整页替换成错误页 | 视图 id 改为**本地状态**，切视图不发任何请求；地址栏用浏览器原生 `history.pushState` 同步；工作台 8+5 个视图路由改静态预渲染（`generateStaticParams`） |
| 10 | 断网后弹出"请输入访问码"，但填了也没用 | 门禁把**网络层失败**（连接被拒）当成了"未授权"，而这两者在客户端看到的都是请求失败 | 网络层失败时放行内容（**服务端鉴权不变**，未授权请求仍返回 401）；前端只对明确的未授权响应要求输入访问码。判定逻辑抽成纯函数 `lib/access-code-gate.ts`，并把**网络层失败**与**HTTP 层失败**严格分开：拿到响应但状态码非 2xx、或响应体不是预期 JSON（例如网关返回 HTML 错误页）时，一律按未授权处理，绝不因"拿到的不是期望内容"而顺手放行 |

修复后的断网实测记录：

| 断网后动作 | 实测结果 |
| --- | --- |
| 课堂场景推进 3/8 → 8/8 | 8 个场景全部渲染正常（讲演页、虚拟仿真、随堂测验、项目任务） |
| 交互仿真拖动「目标距离」滑块 | 读数实时跟随（1.20 m → 1.25 m → 1.30 m）；仿真为本地纯函数，不发请求 |
| 随堂测验作答并提交 | 离线评分正确：1 正确 / 1 错误 / 50%，逐题给出物理解析 |
| 全程浏览器控制台 | **0 error、0 warning** |
| 工作台侧栏切视图 | 8 个视图逐个切换正常，地址栏同步更新，不发请求 |
| 断网下教师端视图切换 | 点侧栏「评价复核」→ 地址栏同步为 `/teacher/evaluation`，6 张学生卡片完整渲染，无白屏 |
| 断网下破坏性动作的撤销 | 重置 → 点「撤销到上一状态」→ 学生卡片与建议分完整恢复，页面未被换成错误页（该路径已去掉 `router.refresh()`，全程不发请求） |
| 命令面板的角色隔离 | 学生面板有「跳到学习报告」无「跳到评价复核」（13 条命令），教师面板反之——跨角色跳转不会造成 URL 与内容错配 |
| 预置包交互 HTML 自包含性 | 源码扫描无 `http(s)://` 外链、无相对路径外部文件引用，CSS/JS 全部内联 |
| 访问码门禁的失败分类 | 断网（fetch reject）→ 放行不弹框；HTTP 401 / 5xx / 响应体非 JSON → 按未授权弹框；判定逻辑由 `tests/access-code-gate.test.ts`（7 项）守住 |

**如实标注的边界**：**跨页面**跳转（首页 → 工作台、首次导入预置包）依赖服务端，
断网时不保证可用。演示动线因此固定为：**先导入预置包并进入课堂，再断网，再播放 / 切视图**。


## 9. 局限与展望

### 9.1 当前局限（如实列出）

1. **数据全部在浏览器本地。** 不跨设备、不跨浏览器；清缓存即丢失。
   这是"无数据库边缘部署"的代价，也是本作品明确的设计取舍。
2. **AI 课堂依赖外部模型。** 无 Key 时只能使用预置包与本地规则引擎，
   多智能体讨论、白板自由演算等能力不可用。
3. **班级画像与成绩为课程示例数据。** 平台没有接真实教务系统，
   所有名单、分数、评价均为演示数据，界面与导出文件中均已标注。
4. **校内实验清单与学时待教务核对。** `lib/school/curriculum.ts` 中
   `isVerified: false` 的条目即为此标记。
5. **未做移动端专项优化。** 侧栏在 768px 以下收为抽屉，表格区域横向滚动，
   但未做触控手势适配。

### 9.2 展望

1. 接 EdgeOne KV 做课程目录索引，实现跨浏览器共享课程列表
2. 引入校方统一身份认证（SSO）替代演示账号
3. 增加第二个物理实验（迈克尔逊干涉仪条纹计数）作为第二个 Interactive 场景
4. 把学情画像反向用于 AI 课堂：让讲解深度随诊断结果自适应
5. 引入真实教务成绩回写，形成"课前诊断—课中课堂—课后评价"的完整数据链
