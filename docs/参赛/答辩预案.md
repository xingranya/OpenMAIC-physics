# 答辩预案（20 条高频问答）

> 回答原则：**先给结论，再给依据**；不确定就直说不确定，不要编。
> 凡涉及"我们没有做"的，直接承认并说明原因与替代方案——评委更认可能力边界诚实。

## 一、关于作品定位

### Q1. 这个作品和 OpenMAIC 是什么关系？你的原创部分在哪？

**A**：OpenMAIC 是清华开源的通用 AI 课堂引擎，提供多智能体编排、课件生成、白板演算、
多场景渲染与导出能力。我们的工作有三块：

1. **教学域**：把《大学物理》的"诊断 → 匹配 → 闯关 → 实验 → 报告"闭环移植进来
   （`lib/physics/`，5 772 行，其中纯领域层 3 777 行），这部分此前不存在于上游。
2. **物理化改造**：在应用层向生成管线注入物理领域约束——符号量纲规范、常见误区、
   实验安全、课程思政、校内上下文与智能体人格。一次注入贯穿课件、测验、仿真、PBL，
   且**没有改动上游任何生成模板**。
3. **校本层与边缘部署**：学校品牌、课程内容、思政落点、校本量表；以及把"必须自建
   PostgreSQL"的架构改造成"浏览器即可"的 EdgeOne 边缘部署形态。

### Q2. 为什么要基于 OpenMAIC，而不是自己写？

**A**：多智能体课堂的核心复杂度在**编排与状态机**——导演循环、轮次控制、白板动作时序、
SSE 流式协议。OpenMAIC 在 JCST 2026 上发表过论文，这部分代码经过大规模验证。
我们把精力放在**教学法**上：过程证据怎么组织、AI 和教师怎么分权、诊断怎么驱动课堂。
自研等于把时间花在重造编排引擎上，教学创新反而做不深。

### Q3. 和市面上其他 AI 教学工具有什么本质区别？

**A**：一句话：**别家给"分数"，我们给"过程证据"，而且教师保留最终判断权。**

具体三点：
- 报告汇总的是过程记录（诊断、模型假设、实验数据、笔记、讨论），分数只是其中一项；
- AI 建议分与教师最终分在界面上是**两个独立字段**，教师值覆盖 AI 值；
- 破坏性动作（重置、重新诊断、切换项目）都有二次确认 + 24 小时可撤销快照。

### Q4. 你的"AI 课堂"里，AI 到底是什么角色？

**A**：三个角色，都明确定义在 `lib/school/campus.ts`：
- **物理教师**（AI 助教）：严谨、擅用生活化类比、强调量纲自检与边界条件；
- **同学 A**：爱追问"这一步为什么成立"；
- **同学 B**：重实验动手，倾向用数据检验想法。
课件里嵌的就是这三套人格。

## 二、关于技术架构

### Q5. 为什么不用数据库？数据存在哪？

**A**：存在**用户浏览器**里：课程文档与学习者运行时在 IndexedDB（OpenMAIC 的浏览器存储
是 1.1.x 的默认实现），学生的诊断/任务/实验记录在 localStorage（版本化包络），
**账号本身也在同一处**（浏览器本地注册，密码经 PBKDF2 哈希后存储，不上传服务端）。
学习记录**按账号分区**（存储键 `physicsAISystem:<userId>`），
换账号看不到上一个账号的诊断分、实验记录与教师复核。

原因有二：一是 EdgeOne Pages 是**无状态边缘运行时**，没有长驻进程也没有固定数据库，
而 OpenMAIC `main` 分支 v1.2.0+ 强依赖 PostgreSQL（缺 `DATABASE_URL` 直接拒绝启动）——
所以我们选 `release/1.1.x` 作基底；二是教学数据留在本地本身也有隐私价值。

代价我们如实写在说明书 §9.1：不跨设备、不跨浏览器、清缓存即丢失。
可选的 EdgeOne KV/Blob 已经预留，用于跨浏览器共享课程目录和生成媒体。

### Q6. OpenMAIC `main` 是不是更好？为什么不用？

**A**：`main` 的能力更多（Agent Workbench、MP4 导出、服务端课程库），但它要求
**常驻进程 + PostgreSQL**，与 EdgeOne 的无状态模型互斥。`release/1.1.x` 保留全部
**AI 课堂核心能力**（生成、编排、白板、多场景、导出），且官方支持 Serverless。
我们把"能力多但部署不了"换成"能力够用且能部署"，并在作品里如实说明取舍。
补充一句取舍的方向：本作品**主动删掉了**上游的 Agent Workbench（`/workbench`、`/workspace`）
与 MP4 视频导出外壳——它们要常驻进程 + PostgreSQL + Docker，与 EdgeOne 的无状态模型互斥。

### Q7. 部署到 EdgeOne 遇到的最大技术难点是什么？

**A**：四个，都已定位并写在部署手册里：

1. **Node 版本**。EdgeOne 可选 22.11.0 / 22.17.1 / 24.5.0，而 OpenMAIC 要求
   `node >= 22.19.0`——前两个都不满足，只能选 24.5.0。
2. **原生模块跨平台**。`sharp` 与 `@napi-rs/canvas` 在 EdgeOne 构建环境是 linux-x64，
   本地是 darwin-arm64。我们在 `pnpm-workspace.yaml` 里声明了
   `supportedArchitectures`，让 pnpm 同时解析 linux-x64 产物，本地与云端共用一份 lockfile。
3. **云函数包有 128MiB 硬上限（这是最硬的一道坎）**。EdgeOne 的 Cloud SSR Node 函数包
   解包后超 128MiB 会被平台直接拒收，错误码 30，原文
   `Cloud SSR Node functions package size exceeds 128MiB limit`。本项目直接部署是
   **254.9 MiB**，超限一倍。定位后拆出三个大头并逐一处理：
   - `sharp` 的 **6 个平台原生变体**（≈133 MiB）。EdgeOne 运行时固定 linux-x64，
     而且 EdgeOne CLI 会给 Next 注入自定义图片加载器，Next 自己的图片优化器根本不
     碰 sharp——所以只有应用自己 `import sharp` 用到的那一份是必需的；
   - opennext 把**项目源码整份拷贝**进函数包（≈34 MiB），运行时真正需要的只有
     workspace 包、`skills/` 和被 `outputFileTracingIncludes` 点名的那一个 mjs；
   - `public/vendor/maic-importer`（≈5 MiB）是 URL 动态 import 的静态资源，
     平台静态托管里已有一份。
   裁剪后 **122.3 MiB**，部署通过。裁剪必须发生在构建之后、上传之前，
   而 CLI 没有暴露这个钩子——我们的取巧办法是：待部署目录里只有 `.edgeone` 时，
   CLI 会判定"产物已就绪"并跳过本地构建。整套流程固化成了
   `node scripts/deploy-edgeone.mjs` 一条命令。
4. **构建产物不能在服务运行期间被替换**。我们遇到过一次"页面文字完全正常，
   但所有按钮静默失效"：运行中的 `next start` 持有旧的 build-manifest，
   它返回的 HTML 按旧 BUILD_ID 引用了磁盘上已被重建删除掉的 chunk，
   chunk 拉不到导致 React 不水合。
   现在部署前后各跑一次"所有客户端 chunk 必须 200"的自检，
   并在部署手册里补上 BUILD_ID 一致性核对，写进了验收清单。

顺带修了 opennext 的两个运行时坑：它注入图片加载器后又把文件删了（运行配置指向
不存在的文件），且把**构建机的绝对路径**内联进了运行配置——本地跑得通是因为那条
路径真的存在，上了平台就不存在。裁剪脚本把两处一并修正。

另外还修了一个上游问题：`build:packages` 在 pnpm workspace 内混用 `npm run build`，
npm 不认识 `workspace:` 协议，CI 下会失败，已改为 `pnpm -r --filter`。

### Q8. "本地确定性引擎"是什么意思？AI 真的在跑吗？

**A**：三级降级，第一级是真 AI：
1. **真实 LLM**——AI 课堂的多智能体讨论、白板自由演算、课件生成；
2. **预置课堂包**——6 个物理章节的完整课堂（讲演页 + 测验，部分另含自包含交互仿真），
   零配额零网络可导入、可播放、可导出；
3. **本地规则引擎**——工作台里的诊断评分、项目匹配、评价建议、实验仿真。

需要说明的是，**工作台的"AI 建议分"来自第 3 级**（本地规则），不是模型推理。
这一点在界面和导出文件里都标注了，不冒充模型输出。真正的模型能力在第 1 级的 AI 课堂。

### Q9. 密钥怎么管理？会不会泄漏？

**A**：默认路径是**服务端环境变量**——EdgeOne 控制台配置，浏览器访问不到，
密钥不进客户端包。浏览器内粘贴 key 只是现场兜底（OpenMAIC 自带的「设置 → 模型服务」），
这种情况下 key 对打开开发者工具的人可见，所以我们在文档里明确标注并建议配合额度上限。
站点本身**没有**全局门禁——原先那把全员共用的访问码已删除，入口换成账号注册 + 登录；
账号与口令在**浏览器本地**注册与校验，不上传服务端。
真正需要保密的只有模型 Key，它仍在服务端环境变量里。

### Q10. 如果评委现场断网或者额度用完了怎么办？

**A**：这正是我们做三级降级的原因。断网时：工作台全功能可用，预置课堂包可导入并完整播放，
交互仿真（自包含 HTML，零外部依赖）照常操作。演示脚本里专门有一镜演示这个。
我们认为教学平台在课堂断网的现实场景里还能用，比什么都重要。

## 三、关于教学设计

### Q11. "过程证据"具体指什么？能举个例子吗？

**A**：以实验验证这一关为例，检查项不是"完成实验"，而是"完成不少于 5 组数据、
计算误差或不确定度、根据数据完成一次方案修改"。最后一项是关键——
**必须有一次由数据驱动的修改**。这与"做完实验填三个数字"是完全不同的学习行为，
而这些记录会原样进入学习报告。

### Q12. 怎么保证 AI 不会给出错误分数？

**A**：两条防线：
1. **AI 不产出最终分**。它只产出建议分和理由，最终分由教师在复核面板给出，
   教师值覆盖 AI 值，学习报告以教师值为准。这条在界面上是常驻可见的。
2. **AI 建议本身要可解释**。每个项目匹配都有可读理由，每条评价建议都带判定依据，
   教师的复核量表（扎实/基本掌握/有缺口/需重建）与 AI 建议共用同一套锚点，
   所以教师能快速判断建议是否合理。

### Q13. 诊断和项目匹配会不会变成"刷题"？

**A**：设计上做了三处抵抗：
- 诊断结果**只用于生成学习建议**，不作为成绩，界面上明确写；
- 匹配理由是**可读的**（覆盖薄弱维度、符合学习方式、适合补强基础），
  不是隐藏分数；
- 项目本身是**跨学科的真实问题**（超声测距、无线传能、导盲眼镜），
  需要建模、采集数据、迭代方案，不是做题能刷出来的。

### Q14. 课程思政怎么落地的？会不会生硬贴标签？

**A**：锚点必须**从该章的真实物理内容自然生长**。举例：讲"牛顿定律与圆周运动"时，
思政落点是"科学方法"——重点不是记住结论，而是说清"模型在什么条件下成立、
超出后为什么失效"，这与工程师做近似、留安全裕量的思维方式同源。
而不是在力学章节硬塞一句"爱科学"。

### Q15. 怎么迁移到其他学校 / 其他课程？

**A**：校本层是**独立模块** `lib/school/`，六个文件：identity（校名班级教师）、
branding（色板字体打印）、curriculum（章节矩阵与实验清单）、ideology（思政锚点）、
rubric（评价量表）、campus（校内语境与智能体人格）。换一个学校就是换这一个目录的内容，
物理域与工作台不用动。代码里全站 grep 不到硬编码的校名字面量。

### Q19. 有没有做用户测试？

## 五、关于现场演示的可靠性

### Q21. 你怎么保证现场"点得动"，而不是"点了没反应"？

**A**：这正是我们这轮最花时间、也最值得说的地方。

**先说踩到的坑。** 构建日志是 `EXIT=0`、页面文字渲染完全正常、浏览器 Console 也是干净的——
但**所有按钮点下去毫无反应**。根因是：某个客户端 chunk 拉不到（404/500），
React 因此**不水合**，于是所有 `onClick` 都不会触发。
SSR 的文字照常显示，看起来"一切正常"。

**这里我们走过一条弯路，值得如实说。** 最初的判断是"standalone 形态与运行期
`output` 判定不一致会让静态资源请求直接抛错"，并试图用 `NEXT_PHASE` 把判定固化到
构建期。**独立复审用对照实验推翻了这条推理链**：在 Next 16.3.3 上用同一份产物、
只改运行期判定值，standalone 与非 standalone 两种形态下当前产物的 41 个客户端 chunk **全部 200**
（chunk 数随前端改动而变，当前值以《作品说明书》§8.1 的自引值为准）。
**真实成因是：运行中的 `next start` 进程与磁盘上的新构建产物不是同一份**——
重建覆盖了 `.next`，旧进程返回的 HTML 仍按旧 BUILD_ID 引用那些已被删除的 chunk。
换成"重建后重启服务进程"症状立刻消失。

（顺带发现 `NEXT_PHASE` 在 `next build` 期间同样取不到值——Next 把它作为
`loadConfig` 的函数入参传入，不是环境变量——于是 `output` 恒为 `undefined`，
standalone 产物永远不再生成；上游的自托管路径（`Dockerfile` / `docker-compose.yml`）已被本作品**整体删除**，
本项目只部署 EdgeOne，所以这段恢复仅保留为环境变量判定的正确性。）

**这个 bug 单测发现不了、构建日志也发现不了，只有真的用浏览器点一下才会暴露。**
所以我们做了三件事：

1. **修根因**：重建后必须重启服务进程（或换新端口），保证 HTML 与 chunk 同源同版本；
   部署手册里补上 **BUILD_ID 一致性核对**，并把 `EDGEONE=1` 写进构建与启动命令。
2. **加门禁**：部署手册给了一条自检命令——页面引用的每一个客户端 chunk 都必须是 200，
   有一个不是就说明要重来。这条命令现在是验收清单里的一节（K 节）。
3. **加自动化**：`scripts/check-physics-e2e.mjs` 固化为 25 项自动检查：
   路由首帧水合安全、chunk 全 200、**BUILD_ID 与目标产物一致**、
   **会话门禁四项**（未登录调高耗能接口 → 401 / 带会话 Cookie → 放行 / 带会话请求头 → 放行 /
   不消耗外部资源的接口不拦）、
   **说明书与部署手册自引 chunk 数与实测一致**、模型降级前提；另用真实浏览器（Chromium headless）
   把学生链 26 步、教师链 16 步、预置包导入播放各跑一遍，
   **要求 0 console error / 0 page error**。每次改版后都会重跑。

**再现场层面的三重保险：**

- **一键入口**：`/login?demo=student` 和 `/login?demo=teacher` 直接进对应角色，
  现场不用记账号密码（角色门禁本身没变，仍是学生进不了教师端）。
- **三级降级**：真实 LLM → 本地确定性引擎 → 预生成课程包。
  后两档各管一段：**本地确定性引擎**负责工作台里的诊断评分、项目匹配、评价建议
  与实验仿真；**预生成课程包**（6 个物理章节，零配额零网络）负责 AI 课堂的"生成"
  环节。断网、没额度、Key 失效，演示都不会中断。
- **24 小时可撤销**：任何破坏性操作（切换项目、重新诊断、命令面板重置）都先写快照，
  工作台顶部有撤销横幅。

我们还在说明书 §8.4 如实列了全部 8 个"只有跑起来才暴露"的缺陷及其根因与修复——
包括那个最难察觉的"页面正常但按钮全哑"。**能构建通过不等于能现场演示**，这是我们最大的体会。

### Q22. EdgeOne 上具体怎么部署的？为什么不推 Git 仓库？

**A**：两条路都准备了，**默认推荐 CLI 直传**：

```bash
edgeone login --site china            # 浏览器授权，登录态存在本机
EDGEONE=1 pnpm build:packages && EDGEONE=1 pnpm build
edgeone makers deploy . --name <项目名> --json
```

不需要先把仓库推到 GitHub/Gitee，现场几分钟就能起一个可访问地址。
CLI 还能直接管环境变量（`edgeone makers env set/ls/pull/rm`），
并且默认会自动把 **AI Gateway 密钥**同步进本地 `.env` 并绑定云端凭据。

如果要正式上线、持续迭代，再走控制台的 Git 导入路径（框架预设 [Next]、Node 24.5.0），
两条路径用的是同一套环境变量模板（`deploy/edgeone.env.example`）。

**模型供给上我们优先用 Makers Models 统一网关**：单一 `MAKERS_MODELS_KEY` 就能调多家厂商模型，
OpenAI 兼容、SSE 原生支持、**内置模型开箱即用**（官方文档「无需绑定自费厂商密钥即可调用」）。
配额上，Makers 目前提供免费版，**Models 网关的内置模型免费额度为 50 万 token/月**、
单个请求最长运行 300 秒（出处：腾讯云《限制与配额》`1552/132789`；
同页里的"20 万次执行/月"是 **Agents** 的配额，本项目**未启用且已删除** Agent Workbench，不适用）。
这意味着**现场不需要自备任何第三方厂商密钥**——只配一个平台内的 Key 就能跑通真实 LLM 链路。

### Q23. 万一评委问"这个数据是真的吗"？

**A**：我们**主动**在界面上标了"课程示例数据，非真实教务数据"：
班级画像、成绩、评价量表全部是示例。平台也**没有**接真实教务系统。
这不是缺陷掩饰，是产品边界——无数据库边缘部署本来就是这个取舍（见说明书 §9.1）。
我们更愿意把"教师复核始终优先于 AI 建议分"这条机制讲清楚：
AI 只给建议分与理由，最终分由任课教师决定并覆盖，这一点在界面、导出文件和报告里都写死了。

### Q24. 预置课堂包里的"项目式学习"是静态内容还是真能跑？

**A**：真能跑，这一点我们专门做了回归。

课堂播放器对 PBL 项目有一套**可运行性校验**（`isRunnablePBLProjectV2`）：
必须至少有一个 `type:'instructor'` 角色，且每个里程碑必须有非空微任务。
判据不过，渲染器会**静默降级**成"项目尚未生成"的占位——页面不报错，只是内容没了。

我们第一版预置包就是踩了这个坑：字段看着齐全，但角色类型和微任务不满足判据。
修复后我们补了一条**直接调用课堂渲染器**的回归测试
（`tests/physics/pbl-render.test.tsx`），把断言从"结构字段齐全"升级为
"真的渲染得出项目、且不出现降级占位"。

这也说明我们的验收方式：凡是"看起来实现了"的地方，我们都补一条
**以最终渲染结果为准**的断言，而不是只校验数据结构。

### Q25. 你们的模型 Key 怎么办？评委现场有 Key 吗？

**A**：我们支持三种配置，现场没 Key 也能完整演示。

1. **首选腾讯云 Makers Models 统一网关**：
   EdgeOne 控制台签发一个 `MAKERS_MODELS_KEY` 即可，
   统一端点 `https://ai-gateway.edgeone.link/v1`，OpenAI 兼容、SSE 原生支持，
   免费版内置模型额度 50 万 token/月（`1552/132789`），**不需要自备任何第三方厂商账号**。
   本项目已原生识别这个变量名，映射到 OpenMAIC 的 `openai` provider。
2. **任意第三方厂商**：DeepSeek / Kimi / MiniMax / Qwen 等，配 `<PREFIX>_API_KEY` 即可。
3. **没有 Key**：生成按钮会置灰并引导去「配置模型」或直接用离线课堂包，
   物理工作台、预置课堂包、导出全流程不受影响——我们实测过工作台全程
   **零模型调用**（网络面板只有 provider 列表与门禁状态两个请求）。

密钥只配在 EdgeOne 控制台的环境变量里，服务端解析，不进客户端包；
也保留了 OpenMAIC 自带的「设置 → 模型服务」页供现场临时粘贴自有 Key。

### Q26. 你们说"断网也能演示"，是真断网测过的吗？

**A**：是，而且这个结论是被实测**推翻过一次**之后才拿到的。

我们原来以为"预置包是纯函数产物、自包含 HTML 不依赖外网，所以断网没问题"。
真正把网络掐断（用一个加载后熄火的本地代理，把应用与后端的连接全部销毁）
逐项操作之后，发现**工作台的视图切换会白屏**：Next.js 15+ 的动态路由客户端跳转
一定要拉一次该路由的 RSC payload，断网时这次拉取失败，框架会把整页换成路由错误页。
而工作台的 8 个学生视图、5 个教师视图其实都是同一个客户端组件按视图 id 挑出来的，
内容根本不需要网络。

修法是把视图 id 提到**本地状态**，地址栏改用浏览器自己的历史记录来同步，
整个切换过程不发任何请求。修完再实测：断网状态下点侧栏，诊断页 8 道题完整渲染、
答题提交后总分与 7 个维度得分全部出来；教师端「评价复核」6 张学生卡片完整渲染；
全程 0 console error / 0 warn。这条也有单测守着
（`tests/physics/view-routing.test.tsx`：视图 id 必须来自上下文而不是路径）。

**要说清边界**：断网时**跨页面**跳转（工作台 → AI 智能课堂）仍需要加载新页面，
做不到；所以演示脚本里我们把"断网前先进入课堂"排在了"断网"之前。

### Q27. 你们的账号系统是怎么做的？强度到哪？为什么不用访问码？

**A**：分四段讲：**为什么放弃访问码 → 注册与登录怎么做 → 口令与数据怎么存 → 门禁守什么不守什么**，
最后**如实说明强度**。

**第一，为什么放弃访问码。** 访问码是**全员共用的一把钥匙**：进门弹一个框，
所有人用同一个口令。它解决的是「别让陌生人随手点进演示站」，
但它**不是账号系统**——没有注册、没有「这份记录是谁提交的」，
所有人的学习数据混在一起。我们要的是后者，
所以入口换成了正常的**注册 + 登录**（`components/physics/login.tsx`：
「注册新账号」/「登录」两个标签，另有一键进入）。

**第二，注册与登录怎么做。** 和物理域其它部分一样分层：
- **纯领域层** `lib/physics/accounts.ts`：注册、登录、口令哈希、会话生成，
  零 React、零 Next.js、零 DOM，可直接单测；
- **浏览器适配层** `lib/physics/account-store.ts`：localStorage 账号仓库、
  WebCrypto（PBKDF2）、会话 Cookie 的下发与清除。

规则都在代码里：账号 3–32 字符（字母 / 数字 / 下划线 / 连字符 / 中文），
身份选学生或教师，**口令至少 8 位**，显示名选填、默认用账号。
「一键进入：学生视角 / 教师视角」以预置演示身份直接进入、不校验口令——
它是**访客体验**，现场演示与应急动线都依赖它，所以保留。
旧的演示账号口令登录（`student` / `teacher` + 公开口令）**仍然可用**。

**第三，口令怎么存，学习数据怎么隔离。**
- 口令用 **PBKDF2-HMAC-SHA256、21 万次迭代**，**每个账号一个随机盐**；
  账号记录里只有盐与派生值，**明文口令绝不落盘**；比对用**常量时间比较**；
  账号不存在时也要走一遍哈希，避免攻击者用响应时间枚举出哪些账号存在。
- 学习数据**按账号分区**：存储键是 `physicsAISystem:<userId>`
  （`lib/physics/local-store.ts`）。换账号**看不到**上一个账号的诊断分、
  实验记录与教师复核；可撤销快照同样按账号分区。
  升级前那一份无作用域的旧数据，只作为**演示学生**的种子继承一次。

**第四，门禁守什么、不守什么。** 这里有个**必须说清的边界**：
- 站点**对所有访问者开放**——没有全局弹框了，匿名访客可以浏览首页与静态页面；
- 只有**会消耗模型额度或上游资源**的接口要求已登录：
  `/api/generate/`、`/api/chat`、`/api/agent/`、`/api/pbl/v2/evaluate`、
  `/api/transcription`、`/api/web-search`；
- 其余接口与页面路由对匿名开放——**拦了会让「断网也能演示」失效**。

同一道门有**三份实现**：客户端下发会话 Cookie、Next 中间件（`middleware.ts`，
本地开发与 Vercel 备份部署用）、以及**云函数入口**
（`scripts/prune-edgeone-function.mjs` 生成的 `createSessionGate`）。
EdgeOne Pages **不部署 Next 中间件**（线上产物的 `middleware-manifest.json`
里 `middleware` 字段是空的），所以**线上真正生效的是云函数入口那份**——
不能靠「写了中间件就算做了门禁」。三份的一致性由
`tests/deploy/session-gate-contract.test.ts` 盯着：Cookie 名、「必须登录」的
前缀列表、形状判定，三处对不上就红。

**最后是强度，如实说：**
- **账号存在浏览器本地**（localStorage），不上传服务端。
  代价是**换浏览器、换设备看不到这些账号，需要重新注册**。
  这不是「服务端账号体系」，我们不这么写。
- **会话门禁只验形状**：会话 Cookie 由**客户端自己写入**
  （内容是账号 id 与登录时间戳），服务器**只能验证 Cookie 的形状，
  验证不了「是不是本人」**。它**挡得住随手匿名调用，挡不住刻意伪造**。
  我们不写「服务端验证了身份」。
- 如果要面向真实教学使用，**下一步应该接学校统一身份认证（SSO）**——
  这一点我们**现在没有做**，不回避。
