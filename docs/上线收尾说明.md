## 二、这轮修了什么

### 1. 上线硬阻塞：登录后调高耗能接口仍然 401

**根因（不是平台、不是 Cookie 名、不是判定逻辑）**：
`scripts/prune-edgeone-function.mjs` 把会话令牌的形状正则写在 **JS 字符串字面量**里，
源文件写的是 `\.` / `\d`（单反斜杠），字符串求值时被吃成 `.` / `d`，
生成进云函数入口的正则于是成了 `/^[A-Za-z0-9._-]{1,128}.d{10,16}$/`
（「任意字符 + 10~16 个字母 d」）——**任何合法令牌都匹配不上**。

**为什么本地查不出来**：本地跑的是 `middleware.ts`（Next 中间件），
**根本不执行这段生成代码**。单测、构建、本地联调因此全绿。

**证据**（修前 / 修后）：

```bash
node -e 'const fs=require("fs");const s=fs.readFileSync("scripts/prune-edgeone-function.mjs","utf8");
const l=s.split("\n").find(x=>x.includes("const SESSION_COOKIE_PATTERN"));
console.log(eval(l.trim().replace(/,$/,"")));'
# 修前：const SESSION_COOKIE_PATTERN = /^[A-Za-z0-9._-]{1,128}.d{10,16}$/;
# 修后：const SESSION_COOKIE_PATTERN = /^[A-Za-z0-9._-]{1,128}\.\d{10,16}$/;
```

**修法**：源文件写成 `\\.` / `\\d`；并让 `tests/deploy/session-gate-contract.test.ts`
**求值生成后的正则**再断言——只匹配源文件子串的断言对这个错误是全绿放行的。
实测：故意去掉一层反斜杠，该测试立刻变红（报
`expected '/^[…]{1,128}\.d{10,16}$/' to be '/^[…]{1,128}\.\d{10,16}$/'`）。

**同时加的冗余保险**：客户端额外发 `x-physics-session` 请求头，门禁**任一合法即放行**；
`readHeaderValue` 兼容 `Headers` / 普通对象（含首字母大写、数组值）/ `rawHeaders` 三种形态；
401 响应带 `x-session-gate-headers`（**只有请求头名字，不含值**），下次排障不用再猜。

### 2. 测试基线脚本的路径归一化 bug

`scripts/test-baseline-lib.mjs` 的 `failedFiles` 用字符串 `replace` 剥前缀。
基线树解在 `mkdtempSync(tmpdir())` 下，而 macOS `/var` 是 `/private/var` 的符号链接：
vitest 报告给 realpath、脚本传的 root 是符号链接路径，**两侧永远对不上**，
于是「本分支引入的失败文件」会把上游本来就在红的文件全部误报（实测报出 30 个
`/privatetests/...` 这种半截路径）。已改为两侧都 `realpath` 归一，并补了符号链接的单测。

## 七、第四轮（2026-10-25 中午）：函数超时抬到 120 秒

### 根因

EdgeOne 云函数**默认单请求上限 30 秒**，而本项目生成链路实测就在 30 秒附近：

| 阶段 | 30 秒上限下 |
| --- | --- |
| 课堂大纲 | 约 32 秒处连接被掐断 |
| 逐场景内容 | 稳定 32.5 秒 → **504 Gateway Time-out** |

官方文档写明 `edgeone.json` 的 `cloudFunctions.maxDuration` 可配 **10–120 秒**
（[限制与配额](https://cloud.tencent.com/document/product/1552/132789) 第 10.1 节）。
之前把这件事当成「模型太慢」去调推理开关，方向错了——**上限本身可以抬**。

### 改动

1. `edgeone.json` 增加 `"cloudFunctions": { "maxDuration": 120 }`。
2. `scripts/deploy-edgeone.mjs` 新增 `assertFunctionMaxDuration()`：**构建前**校验该值，
   缺失或 < 60 秒直接中止部署。它一旦丢失，平台会静默退回 30 秒，症状又变回 504。
3. 同一脚本加 `setDefaultResultOrder('ipv4first')`：Node 默认 IPv6 优先，在 IPv6
   路由不通的网络里 `fetch` 会等到 connect timeout（约 10 秒，报 `fetch failed`），
   而 `curl` 秒回——表现是「加速区域核对未通过」，极易误判成令牌失效。
4. 大纲接口：**已解析出大纲后再中断**（网关提前关连接 / 输出被截断）不再整批丢弃重试，
   直接带着已有结果收尾。重试会把已经花掉的时间再花一遍，两次叠起来必然撞死在上限里，
   最后连可用的 12 个大纲都拿不到。

### 实测

| 验证 | 结果 |
| --- | --- |
| `/api/generate/scene-content`（单场景） | **HTTP 200，103.1 秒**（修复前 504 @ 32.5 s） |
| 课堂大纲（完整流） | **HTTP 200，78.5 秒，15 个场景，收到 `done`** |
| 部署 | `dpt4xvgrhx64`（函数包 119.8 MiB） |

## 八、第五轮（2026-10-25 下午）：把整堂课的生成时间压下来

超时修好后暴露出来的真问题是**总时长**：逐场景内容生成实测 60–82 秒/场，
15 个场景串行要 17–20 分钟。学生看到的是「一直在生成」。

### 做了什么

上游本来就有并行能力（`use-scene-generator.ts` 的两阶段流水线：内容按并发预取、
按顺序消费；动作与 TTS 仍串行），但默认 `PARALLEL_SCENE_CONCURRENCY=0` 关闭——
上游的理由是「很多部署的 Key 并发配额低，默认并发会 429」。

本项目走 Makers 网关，所以按**部署形态**给默认值（`lib/server/provider-config.ts`）：

| 条件 | 并发度 |
| --- | --- |
| 显式设了 `PARALLEL_SCENE_CONCURRENCY`（含 `0`） | 以显式值为准（夹到 0–10） |
| 未设，且有 `MAKERS_MODELS_KEY`（本项目） | **4** |
| 未设，且不是 Makers 托管 | 0（上游行为不变） |

这样不动别人部署的默认，也不需要在平台侧配变量（实测：`env set` 成功但
`/api/server-providers` 仍返回 0——EdgeOne 的环境变量在构建期注入，不重建不生效）。

### 实测

**净对比**（4 个不同场景，只打 `/api/generate/scene-content`，本地直连网关）：

| 方式 | 各场景耗时 | 总墙钟 |
| --- | --- | --- |
| 串行 | 66 / 165 / 54 / 32 s | **317 s** |
| 并行 4 路 | 69 / 71 / 76 / 83 s | **83 s** |

**3.8 倍**，且并行时单请求没有被拖慢（69–83 s 仍在串行单场区间内）。
按 15 场景推算：串行 17–20 分钟 → 并行约 5–6 分钟（含串行的动作生成约 8 分钟）。

线上验证：`/api/server-providers` → `"parallelSceneConcurrency": 4`，
部署 `dpbvx5e5o4vg`。

### 试过但没采用

| 方案 | 结果 | 结论 |
| --- | --- | --- |
| `scene-content` 路由到 `@makers/deepseek-v4-flash` | 一次 30 s（15 元素），同一请求另一次 **500** | 快一倍但不稳定，不做 |

正文内容量对比（同一大纲）：minimax 17–18 元素 / 约 600 字，deepseek 15 元素 / 约 570 字
——差的主要是装饰性图形，正文几乎一样。若后续要再快，可以重试这条路，但需要先解决稳定性。

### 风险

Makers 配额是**瞬时**的：压测期间出现过 `402 insufficient_remaining_quota`
（同一 Key 几分钟后又 200）。并发 4 路会更快撞到窗口上限，现场演示前应确认额度。

枚举可见按钮逐个点击，记录 console error / 4xx-5xx / 是否有可见反馈。

| 范围 | 结果 |
| --- | --- |
| 13 个视图 | 可见按钮 100 次点击，**0 报错**，0 个 4xx/5xx |
| 首页 | 27 个按钮：章节快捷按钮写入输入框（已验证 textarea 值变化）、6 个预置包卡片进入课堂 |
| 课堂页 | 播放器控件默认隐藏（hover 才出现），非缺陷 |
| 登录/注册 | 前几轮已实测：注册、重复名、密码过短、错误口令、演示账号、一键进入 |

审计脚本第一版的「无可见反馈」共 17 个，逐个复核后**全部是误报**：
其中 15 个是「点击当前页自己的侧栏项」（本来就不该有变化），
1 个是 `导出复核汇总`（实际会下载 `教学评价复核-文理学院.md`，只是脚本没监听 download），
1 个是首页章节按钮（写入 textarea，DOM 文本不变）。
