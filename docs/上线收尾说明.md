## 二、这轮修了什么

### 1. 上线硬阻塞：登录后调高耗能接口仍然 401

**根因（不是平台、不是 Cookie 名、不是判定逻辑）**：
`scripts/prune-edgeone-function.mjs` 把会话令牌的形状正则写在 **JS 字符串字面量**里，
源文件写的是 `\.` / `\d`（单反斜杠），字符串求值时被吃成 `.` / `d`，
生成进云函数入口的正则于是成了 `/^[A-Za-z0-9._-]{1,128}.d{10,16}$/`
（「任意字符 + 10~16 个字母 d」）——**任何合法令牌都匹配不上**。

**为什么本地查不出来**：本地跑的是 `middleware.ts`（Next 中间件），
**根本不执行这段生成代码**。单测、构建、本地联调因此全绿。

**证据**（修前 / 修后）：

```bash
node -e 'const fs=require("fs");const s=fs.readFileSync("scripts/prune-edgeone-function.mjs","utf8");
const l=s.split("\n").find(x=>x.includes("const SESSION_COOKIE_PATTERN"));
console.log(eval(l.trim().replace(/,$/,"")));'
# 修前：const SESSION_COOKIE_PATTERN = /^[A-Za-z0-9._-]{1,128}.d{10,16}$/;
# 修后：const SESSION_COOKIE_PATTERN = /^[A-Za-z0-9._-]{1,128}\.\d{10,16}$/;
```

**修法**：源文件写成 `\\.` / `\\d`；并让 `tests/deploy/session-gate-contract.test.ts`
**求值生成后的正则**再断言——只匹配源文件子串的断言对这个错误是全绿放行的。
实测：故意去掉一层反斜杠，该测试立刻变红（报
`expected '/^[…]{1,128}\.d{10,16}$/' to be '/^[…]{1,128}\.\d{10,16}$/'`）。

**同时加的冗余保险**：客户端额外发 `x-physics-session` 请求头，门禁**任一合法即放行**；
`readHeaderValue` 兼容 `Headers` / 普通对象（含首字母大写、数组值）/ `rawHeaders` 三种形态；
401 响应带 `x-session-gate-headers`（**只有请求头名字，不含值**），下次排障不用再猜。

### 2. 测试基线脚本的路径归一化 bug

`scripts/test-baseline-lib.mjs` 的 `failedFiles` 用字符串 `replace` 剥前缀。
基线树解在 `mkdtempSync(tmpdir())` 下，而 macOS `/var` 是 `/private/var` 的符号链接：
vitest 报告给 realpath、脚本传的 root 是符号链接路径，**两侧永远对不上**，
于是「本分支引入的失败文件」会把上游本来就在红的文件全部误报（实测报出 30 个
`/privatetests/...` 这种半截路径）。已改为两侧都 `realpath` 归一，并补了符号链接的单测。

### 2. 默认模型换成 `minimax/minimax-m3`（Makers 渠道）

- 线上环境变量：`DEFAULT_MODEL=openai:minimax/minimax-m3`、`MAKERS_MODELS=minimax/minimax-m3`；
  `/api/server-providers` 返回 `{"openai":{"models":["minimax/minimax-m3"]}}`。
- **必须显式关思考**：MiniMax M3 默认把思考写进正文（`<think>…`），大纲 JSON 直接解析失败
  （线上报「模型未返回有效的大纲内容」）。实测只有 `thinking: { type: 'disabled' }` 生效，
  `reasoning_effort: 'none'` 与 `chat_template_kwargs` 都无效。已在
  `lib/ai/providers.ts` 的 `getCompatThinkingBodyParams` 里对 minimax 默认关闭。
- 关掉后：同一请求 3.3s → 2.4s，输出是纯 JSON。

### 3. 推送即部署（GitHub → EdgeOne）

新增 `.github/workflows/deploy-edgeone.yml`：push 到 `feature/physics-ai-classroom` 时，
在 Actions 上跑「安装 → 构建 → 裁剪 → 体积/泄露门禁 → 上传」，与本地完全同一条流水线。

**为什么不用控制台的「导入 Git 仓库」**：平台侧构建顺序是「安装 → 构建命令 → 平台 opennext
打包 → 上传」，没有构建后钩子；本项目未裁剪的函数包 **180 MiB** > 128 MiB 上限，
裁剪必须插在「打包后、上传前」，平台不给这个时点。

需要一次性配置 Secret `EDGEONE_PAGES_API_TOKEN`（详见 `deploy/README.md` §8.1i）。
